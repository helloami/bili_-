# B站批量评论脚本

基于 `bilibili-api-python` 实现的批量评论工具，可对指定UP主的最新视频自动发送预设评论。提供两个版本：

- `test.py` – 基础版，直接对每个UP主的最新视频发送评论。
- `test_e.py` – 增强版，发送前会检查当前账号是否已在同一视频下评论过，避免重复发送。

## 功能特性

- 自动获取UP主昵称并填充到评论模板中
- 获取每个UP主的最新一条视频
- 向该视频发送自定义评论（支持 `{nickname}` 占位符）
- 支持多UP主批量处理，可配置发送间隔
- 增强版提供“防重复评论”检查（基于B站评论区第一页数据）

## 环境要求

- Python 3.7+
- 安装依赖：`pip install bilibili-api-python`

## 配置说明

打开脚本文件，修改以下配置项：

| 配置项 | 说明 |
|--------|------|
| `CREDENTIAL` | 登录凭证（需要你自己的 `sessdata`、`bili_jct`、`dedeuserid`） |
| `UP_MIDS`   | 目标UP主的UID列表（整数类型） |
| `SEND_INTERVAL` | 每次评论后的等待间隔（秒），建议≥5秒以避免风控 |
| `COMMENT_TEMPLATE` | 评论模板，使用 `{nickname}` 自动替换为UP主昵称 |

### 获取凭证方法

1. 登录B站网页版
2. 打开浏览器开发者工具 → 应用/存储 → Cookies
3. 复制以下值：
   - `SESSDATA`
   - `bili_jct`（即 `csrf`）
   - `DedeUserID`

## 使用方法

### 基础版 (`test.py`)

```bash
python test.py
```
### 增强版（test_e.py）

```bash
python test_e.py
```

运行后脚本会依次处理列表中的每个UP主，输出详细日志。

## 注意事项

- 请确保Cookie有效且未过期，否则会返回 -101 错误。
- 评论频率过高可能导致账号风控，建议适当调大 SEND_INTERVAL。
- 增强版的“去重检查”基于评论区第一页（约20条），若之前评论较靠后可能无法检测到，但足以避免短时间内重复发送。
- 请遵守B站社区规范，合理使用脚本。

## 常见错误码

| 错误码 | 含义    | 解决方法    |
|---|---|---|
| -101   | 账号未登录或Cookie失效 | 重新获取Cookie    |
| -111   | CSRF Token验证失败 | 检查 bili_jct 是否正确 |
| -403   | 操作被拒绝（风控） | 增加发送间隔或更换账号 |
